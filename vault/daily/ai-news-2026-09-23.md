## New Tools & Releases

- ⭐ **Unreal Agent: an open harness from a company nobody had heard of, running the same Terminal-Bench score as Codex for 39% less money.** Unreal Labs published the Go harness **MIT-licensed on 22 Sep** with a runner binary and benchmark runner. The mechanism is async-first: **every tool call runs in the background instead of blocking the model**, so the model never burns turns polling long-running commands. The number: **the same 57.9% pass rate on Terminal-Bench 4.0 costs $1,428 instead of $2,350**. Unreal Labs describes its remit as everything around the model — harness, runtime, inference, and how the three interact. **145 points on HN.** [unreallabs.ai](https://unreallabs.ai/blog/unreal-agent/) · [GitHub](https://github.com/unreallabsai/unreal-agent) · [HN](https://news.ycombinator.com/item?id=49805748)

- ⭐ **Drop: a rootless Linux sandbox with gVisor support, aimed squarely at running coding agents with OS-enforced permissions.** Show HN, 22 Sep. Language independent, **inspired by virtualenv**. Runs inside a Linux user namespace with its own process, mount, network, IPC and cgroup namespaces, and **drops all user-namespace capabilities before executing the sandboxed program**. A TOML config declares which files, dirs and local network services are exposed; a shared base config means new environments need no setup. gVisor is optional, intercepting syscalls for a security boundary without a full VM. The stated use case is explicit: **stop agents deleting data or reaching things they shouldn't, at the OS layer rather than the prompt layer.** [droprun.sh](https://droprun.sh/) · [HN](https://news.ycombinator.com/item?id=49801329)

- ⭐ **Ternary-Bonsai-2-27B: a 27B reasoning model in 5.9GB, retaining 98.2% of its FP16 baseline.** PrismML's ternary quantisation stores nearly every weight as **−1, 0 or +1** with a shared per-group scale factor, landing at **a true 1.72 bits per weight** (2.25 as MLX stores it). Built on Qwen3.8-27B. On a 20-benchmark thinking-mode suite it averages **83.9 against the FP16 baseline's 85.4 — at roughly one ninth the size**. GGUF packings differ by trade-off: PTQ1_0 for footprint, PQ2_0 for faster prompt processing. Currently near the top of Hugging Face trending. **This is the most consequential edge-inference artefact in the window.** [PrismML docs](https://docs.prismml.com/bonsai-2-27b) · [HF (MLX 2-bit)](https://huggingface.co/prism-ml/Ternary-Bonsai-2-27B-mlx-2bit) · [HF (GGUF)](https://huggingface.co/prism-ml/Ternary-Bonsai-2-27B-gguf)

- **gzipt: a language model built from gzip and nothing else — no network, no training, no parameters.** Nathan Barry's write-up on the compression–prediction equivalence. Prime the DEFLATE window with a corpus, then **beam-search candidate continuations scored by compressed length**, because what compresses well is what the model predicts. Generates Shakespeare-like text. The author is honest about the limit: **it's exact substring matching, not pattern recognition**. Useful as a teaching artefact for why "prediction is compression" is not a metaphor. **384 points on HN.** [nathan.rs](https://nathan.rs/posts/gzip-lm/) · [GitHub](https://github.com/nathan-barry/gzipt)

- **Linear cut PR wait time and halved runner time per test while adding ~2,000 tests a week — because agents made CI the bottleneck.** Posted 21 Sep by Mufeez Amjad. **The test suite grew almost 4× since January** while the pipeline stayed flat. Fixes: off GitHub Actions onto faster third-party runners, the **tsgo native TypeScript compiler**, lint rules rewritten to avoid full type-graph builds, minimised critical-path jobs, reworked Vitest sharding. Result: **PR wait from 6+ minutes to just over 5, runner time per test roughly halved.** The framing is the point — when generation gets cheap, **validation becomes the expensive part**. 294 points on HN. [Linear](https://linear.app/now/ci-bottleneck-reworked) · [HN](https://news.ycombinator.com/item?id=49792067)

## Research & Papers

- ⭐ **Jev-Mem cuts agent query latency 36.7% and memory construction time 6.6× by putting a System-One control plane in front of memory.** UT Dallas (Jiang, Li, Li), 22 Sep. Splits agentic memory into a **fast System-One control plane, a multi-relational memory plane, and a System-Two reasoning plane**. On the write path System One does memory typing, redundancy filtering and semantic/temporal/causal/entity relation construction; on the read path, query routing, **retrieval-budget allocation**, graph traversal, candidate scoring, evidence assessment and adaptive stopping. On LoCoMo: **0.777 LLM-as-Judge (+11.0% relative over the strongest baseline), 158s construction (6.6× faster than the fastest competing system), 0.93s average query latency (−36.7%)**. Code and an interactive HF Space released. [arXiv:2609.23986](https://arxiv.org/abs/2609.23986) · [GitHub](https://github.com/libingzheren/Jev-Mem)

- ⭐ **"A Lie Detector Test for Language Models: Reading Knowledge a Model Won't Reveal."** Single-author paper on the 22 Sep HF list. The framing is the useful part for anyone building oversight: it treats **withheld knowledge as recoverable from internals rather than elicitable by prompting** — which is the only version of the problem that survives a model that has learned not to answer. [HF paper](https://huggingface.co/papers/2609.21996)

- ⭐ **RRSI tops the HF daily list at 155 upvotes — and it's from Google, which the 22 Sep briefing didn't note.** New substance on a previously covered item: the regularised recursive self-improvement work (temporal-annealed bundle limits plus a critic/pruner, **+14.1 points on training tasks, +4.7 OOD, 30% fewer policy tokens**) is a **Google** paper, not an anonymous posting, and it finished the day as the most-upvoted paper on Hugging Face. That changes how much weight to put on it. [HF paper](https://huggingface.co/papers/2609.24972)

- **WorldCrafter: a consistent video world model with implicit 3D-aware memory, 113 upvotes.** Tencent ARC Lab, 22 Sep — the second major ARC release in two days after GameHorizon. Addresses the persistent failure mode in generative video: **scene state that doesn't survive camera movement**. [HF paper](https://huggingface.co/papers/2609.24984)

- **D-RAC: retrieval-aware chunking for enterprise documents via PDF normalisation and multimodal markdown conversion.** Yellow.ai, 50 upvotes. Unglamorous and directly useful — the claim is that **chunking should be aware of what retrieval will ask for**, rather than splitting on arbitrary token counts. Relevant to anyone whose RAG quality problem is actually an ingestion problem. [HF paper](https://huggingface.co/papers/2609.24220)

- **EDGEGEN: synthetic edge-case generation for tool-calling agents, from SAP.** Tests agents "beyond happy paths" by generating the failure cases hand-written eval sets don't contain. [HF paper](https://huggingface.co/papers/2609.24115)

- **"1% of Tokens Can Be Enough: On Gradient Estimation in On-Policy Distillation."** Ant Group. If the result holds, on-policy distillation gets dramatically cheaper — **gradient estimation from 1% of tokens**. [HF paper](https://huggingface.co/papers/2609.24432)

- **ShieldVLA: feasibility-aware safety alignment for vision-language-action models.** Microsoft Research. Safety alignment that accounts for whether an action is physically feasible, not just whether it's permitted — the robotics analogue of capability boundaries. ## ⭐ Flagged for Frank

1. **Every tier of the market repriced downward inside a single day, and the right response is to revisit assumptions rather than celebrate.** Opus 5.5 at $4/$20 with cache reads at $0.20, GPT-6 Sol at $2/$10, Luna at $0.10/$0.50, Grok 4.7 at $2/$6 two days earlier, and MiMo-V2.6 free under MIT. Any cost model built before this week is wrong by roughly half, and any workload previously shelved as "too expensive to run at volume" deserves a second look — per-event RG scoring, per-session personalisation, monitoring every agent trajectory rather than a sample. **The second-order implication is the one to act on: the binding constraint on agent monitoring was never really technical, it was the cost of running a model over every trace, and that just halved.** Ornn's finding sharpens it — **open-weight models complete an intelligence-matched task at roughly a fifth the cost of closed ones, and the open frontier now trails the closed one by a median 3.9 months**. For anything on a 6–12 month roadmap, the model you can self-host by delivery will be roughly as good as the API you'd specify today. The caveat to carry into any internal quoting: Anthropic itself says **benchmark margins at this level are a poor guide to real-world differences** — so re-run your own evals rather than repeating the vendor's table.

2. **The Muse filesystem export is a different failure class from the token 0-day two days earlier, and the difference matters for how you write the control.** Wardle's bug was a permissions flaw — something was misconfigured. This one was not: **the agent was asked, in ordinary conversation, to zip its root filesystem and send it to Google Drive, and it did, because both capabilities were legitimately granted.** Out came SSH keys, 113 subagent traces, and unreleased connector configs. No exploit, no injection, no misconfiguration — just two permitted capabilities composing into something nobody intended. That is exactly the shape of the problem in a regulated environment: **an agent with legitimate read access to player data and legitimate access to an outbound connector has, by composition, an exfiltration path that no individual permission review would flag.** The control has to be on capability *combinations* and outbound destinations, not on the permission list. Meta marking the report **"Not Applicable"** tells you something too — vendors do not currently classify composition failures as vulnerabilities, so you will not be told about them.

3. **Ternary-Bonsai and Drop together move genuinely local, genuinely sandboxed agents from interesting to buildable — this is the hackathon item.** A **27B reasoning model in 5.9GB retaining 98.2% of FP16 performance** fits comfortably on a laptop, and **Drop gives you a rootless, capability-dropped, optionally gVisor-backed sandbox to run an agent in without root and without a VM**. Put the two together and you have an agent that reads sensitive data, reasons over it, and acts — with the data never leaving the machine and the blast radius enforced by the kernel rather than a system prompt. For a business where player data residency and processor agreements are a real constraint, **the version of a capability that never makes an outbound call is not a compromise, it's a shorter compliance conversation.** Go.AI's $85M Series A on exactly this thesis — on-prem AI for banks and healthcare, 200+ customers, 8× ARR growth, profitable — is the market confirming it. Worth a weekend: local model, Drop sandbox, one narrow RG or fraud task, measured against the API baseline.

4. **Unreal Agent and Jev-Mem both cut agent cost by fixing the plumbing, which is where the wins now are — and the Linear post explains why that matters more than it sounds.** Unreal Agent gets **the identical Terminal-Bench pass rate for 39% less money purely by not blocking the model on tool calls**; Jev-Mem cuts **query latency 36.7% and memory construction 6.6×** by routing retrieval through a cheap control plane rather than the reasoning model. Neither touched the model. Combined with yesterday's Harness-Zero and RRSI results — and RRSI turns out to be a **Google** paper that finished the day top of Hugging Face, which raises its weight — the consistent picture is that **most agent cost is structural waste, not inference**. The Linear post supplies the second-order implication: as generation gets cheap, **validation becomes the bottleneck** — their test suite grew 4× in eight months and they had to rebuild CI to stand still. If you're planning agent-assisted development, budget for the verification capacity, not just the tokens. **The thing that will slow you down is not the model's speed, it's your ability to check its work.**
