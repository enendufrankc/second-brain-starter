### 2. `game-experience-agent` — `aws` missing from the build image

Three failures yesterday (#2602725, #2602721, #2602703), all identical, all the same job:

```
$ aws ecr get-login-password | docker login --username AWS --password-stdin "$ECR_URI"
/scripts-8248-.../step_script: eval: line 177: aws: not found
Error: Cannot perform an interactive login from a non TTY device
```

`docker_build` runs on `image: docker:27`, which ships no AWS CLI, but the first script line calls `aws ecr get-login-password`. The `.deploy_service` jobs correctly use `amazon/aws-cli:latest`; `docker_build` needs both docker *and* aws and has only docker.

Worth noting: `test_pipeline` **passes**, and the MR pipelines (#2602697, #2602690) are green because `docker_build` is gated on `$CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH`. So this only ever breaks after merge to `main` — the MR looks clean, then main goes red. Nothing has been pushed to ECR or deployed to dev since.

**Fix:** add `apk add --no-cache aws-cli` to a `before_script` on `docker_build`, or switch to an image carrying both CLIs. Also consider running `docker_build` on merge requests so this class of failure is caught pre-merge.
